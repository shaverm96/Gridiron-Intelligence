1 2. System Architecture & Methodology

Gridiron Intelligence is built as a modular, multi-layered system that keeps the user interface separate from orchestration, data access, and agent reasoning. This structure supports both deterministic report generation and more flexible multi-step analysis.

1.1 2.1 Modular Layered Design

The application is organized into four broad layers: * UI layer: Handles page navigation, user input, and report display. * Orchestration layer: Chooses the workflow for recruiting, transfer, or chat requests. * Data and tool layer: Pulls structured records, API data, and web context. * Agent layer: Coordinates planning, evidence gathering, and synthesis.

1.2 2.2 Workflow Orchestration

The system uses two complementary orchestration patterns.

1.2.1 2.2.1 Recruiting Portal (Sequential Enrichment)

The recruiting workflow starts with a structured player record and then enriches it with vector insights, web context, and historical comparables before final synthesis. The goal is to keep the report grounded in stable data while still adding useful current context.

1.2.2 2.2.2 Transfer Portal (Parallel Multi-Source Extraction)

The transfer workflow also begins with structured identity resolution, then gathers supporting evidence from multiple sources in parallel. This keeps the process fast while preserving a clear chain from identity to analysis.

1.2.3 2.2.3 Open Chat (Fan-out/Fan-in Topology)

Open chat uses the same general orchestration pattern, but it is optimized for follow-up questions and context-aware responses. A delegator routes the request, specialized workers gather evidence, and the synthesizer combines the results into the final answer.

1.3 2.3 State and Memory Contract

The system maintains session stability through a dedicated state model. To avoid context growth over time, it uses bounded memory through truncation rather than summarization.

  • State compaction: Only the most recent turns, trace entries, errors, and citations are kept.
  • Bulky context removal: Large intermediate data is cleared after it is no longer needed for the current turn.
  • Session scope: Open chat is seeded from the current report context when available, but it does not carry memory across separate sessions.
